# 阴阳师助手设计说明

## 目标

在 Windows 上提供一个面向 MuMu 模拟器的本地桌面助手，完成三类工作：

1. 导入他人分享的文字方案码或二维码方案，调用游戏内计算能力，从当前账号持有的御魂中完成配装。
2. 当现有御魂不能满足方案时，筛选最值得培养的胚子，按 `+3` 阶段强化、复查结果并在达到预算或潜力不足时停止。
3. 自动循环困 28 和御魂副本，识别体力不足、掉线、界面异常和运行上限并安全停止。

首版不更换满级狗粮，不读取进程内存，不注入游戏客户端，不规避反作弊，也不执行充值、勾玉消费或任何付费操作。

## 产品体验

主窗口由侧边导航和工作区构成：

- “总览”显示 MuMu 连接状态、当前截图、运行任务、最近一次停止原因和今日统计。
- “方案配装”可粘贴 `|TA|...` 文字码或选择二维码图片，展示解析/导入状态、游戏计算结果和缺口。
- “御魂仓库”展示扫描到的御魂、角色定位评分、保护原因、锁定/弃置建议和可搜索表格。
- “强化建议”按收益/成本排序展示胚子，支持预算配置和自动分段强化。
- “日常任务”配置困 28 或御魂副本、循环次数/时间/体力下限并启动。
- 底部常驻运行日志与醒目的停止按钮；全局 `F12` 触发紧急停止。

首次启动执行连接向导：自动查找 MuMu ADB、列出设备、截屏校验、选择游戏分辨率并检查 OCR。运行前展示风险提示，用户确认一次后记录在本地。

## 技术方案

- Python 3.11+。
- PySide6 Qt Widgets 构建 Windows 桌面界面；后台工作放入线程，UI 线程只负责渲染和信号处理。
- 通过 MuMu 自带或用户指定的 `adb.exe` 获取截图与发送点击/滑动/文本输入。
- OpenCV 完成模板与图像区域识别，RapidOCR + ONNX Runtime 完成中文文字识别。
- SQLite 保存设置、任务运行记录、御魂快照、方案和操作审计；不上传账号或截图。
- 领域层保持纯 Python，使评分、组合求解、安全策略和状态机能在无模拟器环境下完整测试。

依赖选择依据：Qt 官方将 PySide6 作为 Qt 6 的 Python 官方绑定；RapidOCR 当前推荐统一的 `rapidocr` 包，并推荐 CPU 使用 ONNX Runtime。游戏自身支持从御魂整理界面导入方案码，近期阵容方案也包含 `|TA|...` 形式的文字码。

## 模块边界

### `domain`

- `models.py`：御魂、属性、方案约束、配装结果、强化候选、保护决定。
- `scoring.py`：输出、控制、辅助、速度四类默认模板和自定义权重评分。
- `optimizer.py`：按六个位置、套装数量、主属性和总属性上下界求解；先做严格求解，失败时返回最小缺口方案。
- `upgrade.py`：用当前词条、潜在强化次数和方案缺口排序胚子，生成 `+3` 阶段动作。
- `safety.py`：集中处理不可弃置、不可作为材料、禁止消费和停止条件。

### `infrastructure`

- `adb.py`：ADB 发现、设备列表、截屏、点击、滑动、文本输入和超时。
- `vision.py`：OCR、文字框查找、模板匹配和归一化坐标换算。
- `repository.py`：SQLite 仓储与迁移。

### `automation`

- `engine.py`：可取消的有限状态机。每次动作前重新截图并验证场景；动作后等待可观测状态变化。
- `workflows.py`：困 28、御魂副本、方案码导入、御魂扫描、锁定/弃置、阶段强化和装配工作流。
- `guards.py`：连续识别失败、画面不变、体力不足、网络错误、背包满、运行次数/时间上限等守卫。

### `ui`

- `main_window.py`：导航、页面容器、状态栏、停止按钮和任务协调。
- `pages/`：总览、方案配装、仓库、强化建议和日常任务页面。
- `workers.py`：将截图、扫描和自动化任务隔离到后台线程。

## 数据流

1. 连接 MuMu 后，ADB 截图进入视觉层；视觉层只返回结构化的文字框、场景和置信度。
2. 方案码优先通过游戏内入口导入，让游戏按当前账号库存计算；助手读取计算结果与未满足约束。
3. 御魂扫描把详情页 OCR 结果标准化后写入 SQLite。低置信度记录标记为“待复核”，不得自动弃置或作为材料。
4. 优化器从高置信度库存中求六件套；若严格解不存在，缺口传给强化规划器。
5. 强化规划器选择未装备、未锁定且受预算允许的胚子，每次只强化 3 级，然后重新扫描、评分和决定继续或止损。
6. 所有点击、锁定、弃置、强化和装配动作写入审计日志，包含前置场景、置信度、坐标和结果。

## 御魂规则

默认模板只提供合理起点，不声称存在唯一评分标准：

- 输出：暴击、暴击伤害、攻击加成、速度。
- 控制：效果命中、速度、生命加成、防御加成。
- 辅助：速度、生命加成、效果抵抗、防御加成。
- 速度：速度优先，其余按有效词条补分。

严格保护以下御魂：已装备、已锁定、OCR 置信度低于 `0.92`、六星且含速度胚、六星且至少三个有效副属性、或被任一已保存方案引用。保护规则只允许在设置中逐项关闭，禁止“一键全部关闭”。

强化预算包含金币上限、材料上限、单枚最高等级、单次任务最多御魂数和最低预计收益。默认 `+3` 检查点，强化结果偏离目标时立即止损。随机词条只做区间与期望估计，不承诺必然达标。

## 自动化状态机

困 28 的核心状态为：主页/探索入口 → 章节 28 → 困难难度 → 地图找怪 → 战斗中 → 结算 → 地图。无可点击怪物时刷新或退出重进；首版不替换狗粮。

御魂副本的核心状态为：御魂入口 → 层数/阵容确认 → 战斗中 → 结算 → 再次挑战。支持次数、时长、体力阈值任一达到即停止。

任何状态出现以下情况都进入安全停止：三次无法识别、截图在动作后持续不变、出现网络错误/登录页、体力不足、背包满、操作目标置信度低于阈值、ADB 断开或用户按下 `F12`。

## 错误处理

- ADB 不存在：连接向导展示自动搜索过的路径并允许浏览选择。
- 多个设备：明确显示序列号与分辨率，保存用户选择。
- OCR 低置信度：记录截图和字段，不产生破坏性动作。
- 工作流异常：停止输入、保存最后截图与状态、在 UI 中给出可执行的恢复建议。
- 数据库错误：只读模式启动并允许导出日志，不继续自动化。

## 测试与验收

- 单元测试覆盖模型校验、评分、保护规则、严格/近似配装、强化候选、状态机转换和停止守卫。
- ADB 合约测试使用可执行假程序验证命令参数、超时和 PNG 数据，不依赖真实模拟器。
- 视觉测试使用项目自带的合成图片，不提交游戏版权截图。
- UI 冒烟测试验证窗口可创建、页面切换和停止信号；真实 MuMu 验收需在用户机器上完成连接向导。
- 完成标准：测试全绿、静态编译通过、README 可从零安装启动、无模拟器时使用演示数据仍可体验评分/配装流程。

## 发布与限制

仓库默认不包含游戏图片、账号信息或用户截图。`data/`、日志和数据库加入忽略列表。首版以源码运行并提供 PowerShell 启动脚本；稳定后再使用 `pyside6-deploy` 或 PyInstaller 生成 Windows 安装包。

游戏 UI 更新可能使识别规则失效，因此场景文字、区域和阈值都放入版本化配置。用户需自行判断使用自动化是否符合游戏服务条款并承担账号风险。
